# HookHub

[![CI](https://github.com/pjsoliveira/hookhub/actions/workflows/ci.yaml/badge.svg)](https://github.com/pjsoliveira/hookhub/actions/workflows/ci.yaml)

A catalog of community [Claude Code hooks](https://code.claude.com/docs/en/hooks). Hooks show up as cards, each card links to the hook's GitHub repository, and you can filter by the hook event they react to (`PreToolUse`, `Stop`, and so on).

**Live site:** <https://hookhub-beta.vercel.app>

## What you can do

- **Browse** every listed hook as a card, with its description, install method, the events it handles, and its GitHub stars, license and last update.
- **Filter by event.** Pick one or more of the 33 hook events; you see hooks that handle **any** of them.
- **Search** by name, description, repository, event or tag.
- **Sort** by stars (the default), last updated, newest added, or name.
- **Share a view.** Filters live in the URL, for example `/?event=PreToolUse&event=Stop&q=format&sort=name`.
- **Open a hook's page** (`/hooks/<slug>`) for what each of its events does, how to install it, its language and license, and the month its events were last checked against the repo.

## Quick start

You need Node.js **22.18 or newer**.

```bash
npm install
npm run dev        # http://localhost:3000
```

| Command | What it does |
|---|---|
| `npm run dev` | dev server on port 3000 |
| `npm test` | unit and component tests (schema, catalog integrity, filtering, components) |
| `npm run typecheck` | generate route types, then `tsc --noEmit` |
| `npm run lint` | ESLint |
| `npm run build` | production build; also validates the catalog, so a bad entry fails the build |
| `npm run refresh:github` | refresh `data/github-meta.json` from the GitHub API (set `GITHUB_TOKEN` for a higher rate limit) |

## How the catalog works

The catalog is **curated by hand**: `data/hooks.json`. GitHub topic search is too noisy to use as a source (most results are guides or whole toolkits, not hooks). GitHub is only used to refresh stars, license and last push, and the site never calls it at request time.

| File | What it is |
|---|---|
| `data/hooks.json` | One entry per hook. Validated by `src/lib/hooks/schema.ts` at build time. |
| `data/events.json` | The 33 hook events, with exact names from the [official docs](https://code.claude.com/docs/en/hooks). When Claude Code adds an event, add it here. |
| `data/github-meta.json` | Generated by `scripts/refresh-github.mjs`. **Don't edit it by hand.** |

The build fails if an entry is invalid, if a slug or repo is listed twice, if a hook names an event that isn't in `events.json`, or if `hooks.json` and `github-meta.json` don't match.

## Add a hook

Anyone can propose one with a pull request.

1. **Check the repository first.** Read its README and its hook configuration (`hooks/hooks.json` or `.claude/settings.json`) and note which events it actually registers. Don't guess. Only list repos that are focused hooks, not guides, toolkits or marketplaces.
2. **Add an entry** to `data/hooks.json`:

   ```json
   {
     "slug": "my-hook",
     "name": "My Hook",
     "description": "One sentence, plain text, 200 characters at most.",
     "repo": "owner/name",
     "events": ["PreToolUse"],
     "install": "plugin",
     "tags": ["git"],
     "addedAt": "2026-10-10",
     "verifiedAt": "2026-10-10"
   }
   ```

   | Field | Rules |
   |---|---|
   | `slug` | kebab-case, unique |
   | `name` | 1–80 characters, plain text |
   | `description` | 1–200 characters, plain text |
   | `repo` | `owner/name` only, unique; links always go to `github.com/{repo}` |
   | `events` | 1–40 unique names, each one present in `data/events.json` (case-sensitive) |
   | `install` | `plugin` (ships a `hooks/hooks.json`), `settings` (copy entries into `settings.json`) or `script` (installed by a script or package) |
   | `tags` | optional, up to 10, each up to 30 characters |
   | `addedAt`, `verifiedAt` | dates as `YYYY-MM-DD`. `verifiedAt` is the day you checked `events` against the repo's real hook config. The site shows it, because repos change. |

3. **Run the checks:**

   ```bash
   npm run refresh:github && npm test && npm run build
   ```

   `refresh:github` adds the new repo's stars, license and last push to `data/github-meta.json`.
4. **Open a pull request.** CI runs the same checks.

### With Claude Code

This repo ships a skill and an agent that do steps 1–3 for you. In Claude Code, run `/add-hook owner/name`. The read-only `hook-verifier` agent (`.claude/agents/hook-verifier.md`) reads the repo's real hook configuration, reports a verdict with evidence, and proposes the entry. The skill (`.claude/skills/add-hook/SKILL.md`) then updates `data/hooks.json` and runs the checks. It also re-checks a hook that is already listed.

## Automation

- **CI** (`.github/workflows/ci.yaml`) runs on every pull request and every push to `main`: typecheck, lint, tests and a production build.
- **Weekly refresh** (`.github/workflows/refresh-github-meta.yaml`) runs on Mondays at 06:00 UTC, and can be started by hand. It updates stars, license and last push for every listed hook, runs the tests and the build on the new data, and only then commits it. If a repo was archived, has disappeared, or the API was rate limited, it still commits the good data and then fails the job so someone looks at it.
- **Hosting.** The site is on Vercel, connected to this repository.

## Project layout

```
data/               hooks.json, events.json, github-meta.json
scripts/            refresh-github.mjs and its helpers
src/
  app/              pages: the home page and /hooks/[slug], plus robots.ts and sitemap.ts
  components/       HookBrowser (filters), HookCard, hero variants
  lib/hooks/        schema, loading, filter/sort/URL logic (pure functions, tested)
.github/workflows/  CI and the weekly metadata refresh
.claude/            the add-hook skill and the hook-verifier agent
```

Built with Next.js 16 (App Router, Cache Components), React 19, TypeScript, Tailwind CSS and Zod, tested with Vitest.

## Notes

- Names and descriptions are rendered as plain text, never HTML, so a catalog entry can't inject markup.
- Links go only to `github.com/{owner}/{name}`; the schema rejects anything else.
- `/robots.txt` and `/sitemap.xml` are generated from the catalog at build time (`src/lib/seo.ts`), so a new hook shows up in the sitemap automatically. Their URLs use `https://hookhub-beta.vercel.app`; when the site gets a custom domain, set the `SITE_URL` environment variable (or change the default in `src/lib/site.ts`).
- Hooks run commands with your permissions. The detail pages tell people to read a hook's code before installing it, and so should you.
